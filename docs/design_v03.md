# Regional Intelligence Radar v0.3.0

## 概要と現在のミッション

Regional Intelligence Radarは、地域創生、地域活性化、自治体DX、行政施策、地域課題に関する良質な一次情報を、運営メンバーやリーダーが効率よく閲覧・検索するためのWebアプリです。

シグナルレーダーはすでに運用されており、運営メンバーからの「とにかく一次情報を有益なものにしてほしい」という要望を受け、情報の改善を重ねてきました。有益な情報を継続して得られる段階に到達した現在のミッションは、**蓄積された良質な一次情報を、優れた可視化によって、少ない認知負荷で理解し、必要なときにすぐ取り出せるようにすること**です。

情報の発見可能性を検証するPoCや、仮説・実験へ進むためのプロセスを製品の目的とする段階は終了しています。情報の質を維持しながら、閲覧・探索・検索の体験を改善します。

本書はv0.3の製品方針と目標とする動作を定めます。v0.2の設計書は旧版として扱い、追加機能の段階的な実装と進捗は[追加機能計画](design_feature.md)で管理します。追加機能の実装状況と検証結果は追加機能計画に記録します。機能1の全期間検索を実装し、機能2〜4は未着手です。旧資料にあるPoC目的やSignalから仮説・実験へ発展させる方針より、本書のミッションを優先します。

## 利用者と利用場面

主な利用者は、毎週のMTGで地域情報を共有する運営メンバーとリーダーです。会議で使うPCに加え、手元のスマホで短時間に開いて確認できる体験を重視します。

- 自治体や行政との会話中に、「先月ほかの市がやっていた事例」を検索する。
- 「マイナンバーを活用した事例」のように、覚えている言葉から過去の共有内容を探す。
- 訪問やMTGの前に、特定の市町村についてどんなニュースがあったか時系列で振り返る。
- 空いた時間に、最新週のニュースを軽く眺める。
- 会議では、日本地図から情報の地域的な分布を俯瞰し、気になる地域の詳細を確認する。

## 可視化と情報設計の原則

### 日本地図を主要な探索手段として維持する

日本地図による表示は運営メンバーから好評を得ています。地域の位置や情報の分布を直感的に把握できる、製品の中核となる可視化です。検索を追加しても、日本地図の価値を維持します。

地図・一覧・詳細を連動させ、「どこの情報か」「何があったか」「詳しく知るにはどこを見るか」を自然に理解できるようにします。検索や最新週から開いた事例でも、自治体名と都道府県を確認できるようにします。

### 読む量と操作の迷いを減らす

文字だけの一覧に依存せず、地図、日付によるグルーピング、タイムライン、カード、トピック表示、検索語の強調を目的に応じて使います。視覚表現は情報の位置・時期・分類・選択状態を伝えるために用い、装飾によって理解を妨げないようにします。

一覧では自治体・日付・タイトル・短い概要を整理して提示し、必要に応じて詳細へ進めます。長文や操作項目を最初からすべて並べず、短時間の流し読みと詳しい確認を両立させます。色だけに意味を持たせず、ラベルや形、配置でも区別します。

一次情報の内容と、注目する理由・期待される機会などの解釈を区別し、出典への導線を維持します。`opportunity` は既存データの項目として保持しますが、機会の創出を閲覧体験の目的には据えません。

### 既存の視覚的な特徴を活かす

Intelligence Console / Operations Centerの雰囲気を維持します。固定のダークテーマ、控えめなシアン、細い境界線、微かな発光、整理された情報密度、限定的な等幅書体を用います。ユーザー向けの説明・カテゴリ・状態は自然な日本語とします。

動きは軽く控えめにし、`prefers-reduced-motion` に対応します。操作にはキーボードでも到達でき、選択状態と操作名が分かるようにします。

## 画面の入口と地域選択

| 入口 | 役割 |
|---|---|
| 最新週 | 最新の共有内容を短時間で眺め、過去週へ移動する |
| 探す | キーワードから全期間の過去事例を取り出す |
| 地図 | 全国の情報の分布を俯瞰し、都道府県から探索する |

地図で都道府県を選ぶと、その地域の事例を表示します。同じ都道府県の再選択や「地域選択を解除」で地域指定を解除し、地図の倍率・位置は維持します。

一覧に事例がある場合、詳細は表示中の一覧に含まれる事例を指します。絞り込み条件を変更した場合は先頭の該当事例を選択し、0件の場合は空表示として以前の詳細を残しません。

最新のレポート週とアーカイブ全体の件数を確認できるようにし、絞り込み後の件数とは区別します。検索条件と地図の都道府県指定はANDで組み合わせます。地域解除は都道府県のみ、全条件解除はキーワードと都道府県を解除します。地図の倍率・位置と全体件数は維持します。各入口間の条件の引き継ぎは機能4で確定します。

## v0.3で追加する4機能

以下の順で、1機能ずつ仕様を確定し、実装・検証します。すべてLLM APIなしで実現します。

### 1. 全期間を対象にしたキーワード検索

- タイトル、概要、自治体名、関連トピック、注目する理由を対象に、週をまたいで検索する。
- 検索操作は複数キーワード検索のみ。自治体選択・期間指定・並び順の切り替えは設けない。
- 検索結果に自治体名・日付と一致箇所の抜粋・強調表示を出し、詳細を開かずに探していた情報か判断できるようにする。
- 条件の解除と該当なしの表示に対応する。

空白区切りのAND検索とし、異なる項目にそれぞれ一致しても対象とします。NFKCと小文字化で照合し、関連トピックは元の値と日本語表示名の両方を検索します。抜粋は項目名付きで最大3件とし、元の文字列を維持して強調します。

検索結果はレポート週の新しい順に固定し、同じ週ではアーカイブ順を維持します。自治体名もキーワードで検索できます。検索条件変更時は一覧の先頭へ戻し、日本語IMEの変換中は検索の適用を保留します。

一覧見出しの下にキーワード検索欄を置きます。「詳細条件」、自治体選択、期間・並び順の基準、開始日・終了日は廃止し、再追加しません。地図の都道府県選択は維持します。スマホでは検索欄の下に高さ480pxの結果スクロール領域を配置します。入口全体の再構成は機能4で扱います。

表記揺れ辞書、関連度順の順位付け、入力中の検索候補は追加候補です。初回実装の必須機能には含めません。

### 2. 自治体ごとの履歴・タイムライン

- 自治体名の検索や事例内の自治体名から、その自治体の過去情報へ進める。
- 日付の流れを視覚的に追える形で表示し、概要とトピックを確認できるようにする。
- 初期表示は新しい順とし、古い順への切り替えと自治体内検索に対応する。
- 同名の自治体は都道府県で区別する。

ニュースの公開日とレポート週は区別します。「先月聞いた話」と「先月公開されたニュース」は同一ではありません。現在のJSONには実際のMTG日は含まれないため、レポート週を実際の会議日とはみなしません。

### 3. 最新週をサッと読める表示

- 最新の取り込み週の情報を、自治体名・タイトル・短い概要・注目する理由を整理したカードで表示する。
- 「最新週」と対象日付を明記し、現在の暦週と混同させないようにする。
- データが存在する前後の週へ移動できるようにする。
- 詳細を読んだ後に、一覧の読んでいた場所へ戻れるようにする。

### 4. スマホで検索から始められる画面

- 「最新週・探す・地図」へ分かりやすく移動でき、検索の前に大きな地図をスクロールする必要がない構成にする。
- 詳細から戻ると、検索条件と一覧のスクロール位置を復元する。
- 日本地図へのアクセスを維持し、手元の画面でも地域を視覚的に探索できるようにする。

先行する3機能も追加時点からスマホで利用できるようにし、この段階で入口と戻る導線を全体として整えます。

## レスポンシブ表示

360px幅のスマホから1440〜1920pxの横長ディスプレイまで対応します。ヘッダーの操作と統計を各画面幅で確認できるようにします。

スマホでは、短時間の検索と流し読みを優先します。地図・一覧・詳細を常に固定順で縦に積むことや、地図・一覧を一律480pxにすることは要件にしません。主要な操作領域は44px以上を確保し、詳細への移動・復帰では表示位置とフォーカスを適切に扱います。

PCでは地図と情報を見比べる既存の構成を活かします。既存の地図55%、右領域内の一覧70%という初期配分と、ドラッグ・キーボードによるサイズ変更を地図表示の出発点にし、追加する検索・閲覧体験に合わせて検証します。

## 情報の取り込みとデータ構造

毎週のMTGで共有する情報をJSON形式で手動配置し、過去週も蓄積して利用します。情報収集工程や外部のレポート作成手段は本書では規定せず、提供された良質な情報の表示・探索・検索を対象にします。自動収集・自動同期やアップロードUIは今回追加しません。

SignalデータはTypeScriptファイルに直接定義せず、`data/YYYY-MM-DD.json` として週単位で配置します。新しいJSONの追加に伴うコードや設定の変更、`index.json` の更新は不要です。

- `app/`：ページの入口と全体のスタイル。
- `components/`：画面の状態管理と表示部品。
- `types/`：`Signal`、`WeeklySignalData`、`ArchivedSignal` などのデータ契約。
- `data/`：手動配置する週次JSON。
- `lib/`：アーカイブ読み込み、検索・絞り込み、表示用メタデータ。
- `docs/`：製品方針と設計・実装計画。

ページで検証済みアーカイブを読み込み、画面へ渡す既存の境界を維持します。表示部品は週次JSONを直接読み込まず、検索処理を表示から切り離します。今回の4機能のためにAPIやDBを新設することは前提にしません。

## JSONフォーマット

各JSONは1週間分のSignalを保持します。以下はサンプルです。

```json
{
  "week": "2026-08-24",
  "generatedAt": "2026-08-24T09:00:00+09:00",
  "signals": [
    {
      "id": "2026-08-24-001",
      "prefecture": "長野県",
      "municipality": "○○市",
      "category": "Regional Mobility",
      "title": "AIオンデマンド交通の実証実験を開始",
      "summary": "高齢者や交通空白地域の移動手段確保を目的とした実証実験。",
      "importance": "HIGH",
      "publishedAt": "2026-08-20",
      "whyItMatters": "人口減少地域における公共交通維持の新しいアプローチとして注目できる。",
      "opportunity": "地域通貨、健康施策、高齢者支援との連携可能性がある。",
      "relatedTopics": [
        "Regional Mobility",
        "Aging Society"
      ],
      "sourceUrl": "https://example.com"
    }
  ]
}
```

`lib/loadSignalArchive.ts` は `import.meta.glob` によって週次JSONをサーバー境界で自動検出します。ファイル名と `week` の一致、日付・日時の形式、対応カテゴリ・重要度、URL、アーカイブ全体でのIDの一意性を検証します。検証済みデータは最新週から降順のアーカイブとなり、各事例には由来となる `reportWeek` が付きます。

公開日・レポート週・出典を安定して保持し、検索や時系列表示に利用します。ブラウザからローカルファイルシステムを直接参照する仕組みは追加しません。

## 将来の拡張と今回の対象外

4機能の実装後に、関連する過去事例、あとで読む・お気に入り、事例への直接リンク・要点コピー、閲覧・検索履歴を検討します。これらもLLMなしで実現できます。

将来はLLMを接続し、曖昧な記憶からの検索、自治体の動向や週次情報の横断要約を検討します。今回接続を実装することはせず、キーワード検索と地図の地域選択、元の情報と出典に戻れる構造を整えます。

セキュリティ要件と公開環境は別途扱います。個人利用・完全ローカル限定を製品の前提には置かず、メンバーが必要な場面で開ける閲覧体験を設計します。

## 完了の判断と段階的な検証

成功の基準は、必要な事例を会話中に見つけられること、自治体の過去情報を迷わず追えること、最新週の情報を短時間で理解できることです。地図の分かりやすさを保ち、文章を順番に読まなければ情報を探せない状態を減らします。

各機能の着手時に、未確定の機能の並び順・入口間の状態保持を必要な範囲で確定します。完了条件と進捗は追加機能計画へ反映し、AGENTS.mdとプロジェクトスキルも確定した製品方針・動作に整合させます。

実装後はビルド・lintと該当する自動テストに加え、360pxのスマホとPCで検索、条件解除、0件表示、詳細への移動と復帰、地図操作を確認します。ビルド成功と視覚的な使いやすさの確認は分けて記録し、実際の会議・会話・流し読みでの使い勝手を継続して改善します。
