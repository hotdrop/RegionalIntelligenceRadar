# 追加機能の実装方針

本書はv0.3の追加機能計画です。以下の実装方針を基準とし、後半にはユースケースと提案の詳細を残します。詳細に含まれる追加候補や将来の構想は、今回の必須実装には含めません。

## 今回の実装対象と順序

次の4機能を、1つずつ仕様確認・実装・検証して進めます。すべてLLM APIなしで実現し、週次JSONを手動で取り込む運用を維持します。

1. 全期間を対象にしたキーワード検索
2. 自治体ごとの履歴・タイムライン
3. 最新週をサッと読める表示
4. スマホで検索から始められる画面

各機能は追加時点からスマホで利用できるようにし、4では「最新週・探す・地図」の入口と、詳細から戻る導線を全体として整えます。各節のステータスは実装・検証の進捗に合わせて更新します。

## 必須機能と将来の拡張

検索の初回実装では、複数キーワード検索と一致箇所の抜粋・強調表示を必須とします。2026-09-26の方針変更により検索操作はキーワード検索のみとし、自治体・期間・並び順の指定は廃止して再追加しません。表記揺れ辞書、関連度順の順位付け、入力中の検索候補は追加候補とし、初回の完了条件には含めません。

関連する過去事例、あとで読む・お気に入り、事例への直接リンク・要点コピー、閲覧・検索履歴は、4機能の実装後に検討する拡張です。LLMによる曖昧検索や横断要約も将来の拡張とし、今回は接続を実装しません。将来の接続に備え、検索処理と画面を分離し、事例ID・自治体名・日付・出典、事実と解釈の区別を維持します。

セキュリティ要件や公開環境の整備は、本書の実装対象に含めません。

## 既存設計との関係

本書は、[製品設計](design_v03.md)に基づく段階的な実装計画です。旧版の「都道府県のみで絞り込む」という制約はキーワード検索の追加で更新し、スマホの入口全体の再構成は機能4で扱います。

各機能の実装時に、該当する既存設計・[AGENTS.md](../AGENTS.md)・[プロジェクトスキル](../.agents/skills/regional-intelligence-radar/SKILL.md)を、その機能の確定仕様に合わせて更新します。未実装の機能を実装済みとして記載せず、今回変更しない既存の方針は維持します。

# 回答
この用途なら、**「会議で地域情報を俯瞰する画面」に加えて、「会話中に過去の事例をすぐ引き出せる機能」**を充実させるのがよさそうです。

現在の実装には、過去週の蓄積・都道府県による絞り込み・事例の詳細表示があります。キーワード検索は機能1で追加し、自治体別の履歴表示は機能2で扱います。優先順位としては、以下の4つをおすすめします。セキュリティや公開環境の話は含めていません。

## 1. 全期間を対象にしたキーワード検索〈最優先〉
- ステータス: 実装済み（自動テスト・主要ブラウザ操作を確認、IME実機操作と動きを抑える設定での実動作は未確認）

### 確定仕様

- 全アーカイブを対象に、空白区切りのAND検索。異なる項目への一致も組み合わせる。NFKC・小文字化で全角半角と英字の大小を吸収する。
- 対象はタイトル・概要・自治体名・関連トピック（元の値と日本語表示名）・注目する理由。抜粋は項目名付きで最大3件、元の文字列の一致部分を強調する。
- 検索操作はキーワード検索のみ。「詳細条件」、自治体選択、期間・並び順の基準、開始日・終了日は廃止し、再追加しない。自治体名はキーワードとして検索できる。
- レポート週の新しい順に固定し、同じ週ではアーカイブ順を維持する。公開日とレポート週は表示情報として残す。
- 条件変更で先頭結果を選び、一覧スクロールを先頭へ戻す。0件では以前の詳細を残さない。IME変換中はキーワード適用を保留する。
- キーワードと地図の都道府県指定はANDで組み合わせる。地域解除は都道府県のみ、全条件解除は両方を解除する。地図の倍率・位置、全体件数は維持する。
- 一覧見出しの下にキーワード検索欄と、入力・地域選択がある場合の解除操作を配置する。スマホは検索欄を自然な高さ、結果一覧を480pxのスクロール領域とする。入口全体の再構成は機能4で扱う。
- API・DB・外部検索・依存ライブラリは追加しない。条件の永続化やURL保存、詳細内の強調は対象外。

### 利用イメージ

「マイナンバー」「窓口」「子育て」など、覚えている言葉から過去の事例を探せる機能です。

- タイトルだけでなく、概要・自治体名・関連トピック・注目する理由も検索する。
- 「マイナンバー 子育て」のように複数の言葉で絞り込める。
- 検索結果に、一致した部分の抜粋と強調表示を出す。
- 自治体名もキーワードに含めて検索できる。

特に、**詳細を開かなくても「探していたのはこれだ」と判断できる検索結果**が重要です。自治体名・日付・概要の一部が見えると、会話を止めずに確認しやすくなります。

最初は文字検索で十分ですが、「マイナカード／マイナンバーカード」のような表記揺れを補えると、さらに使いやすくなります。

## 2. 自治体ごとの履歴・タイムライン〈優先度：高〉
- ステータス: 未着手

自治体名を検索、または事例内の自治体名をタップすると、その自治体について過去に共有したニュースをまとめて見られる機能です。

- 初期表示は新しい順。施策の経緯を追うときは古い順に切り替える。
- 各事例に概要とトピックを表示する。
- 自治体内でもキーワード検索できる。
- 同名の市町村は都道府県付きで区別する。

「YY町とのMTG前に、過去に何があったか軽く確認する」という事前準備にも使えます。

ここでは、**ニュースの公開日と、週次MTGで共有した時期を分ける**のがおすすめです。「先月聞いた話」は、先月公開されたニュースとは限らないためです。現状も公開日とレポート週を持っているので、それを活用できます。実際のMTG日が必要なら別途記録します。

## 3. 最新週をサッと読める表示〈優先度：高〉
- ステータス: 未着手

最新の取り込み週だけを、スマホで流し読みできる入口です。

- 自治体名・タイトル・短い概要・注目する理由をコンパクトに並べる。
- 気になる事例を開き、読んだ場所へ戻れる。
- 前週・翌週へ簡単に移動できる。
- 対象週を明記し、新しいデータがない場合も最新週が分かる。

「今週」という名前だけだと更新がない週に誤解しやすいため、**「最新週：9/○○」のように日付も表示する**とよさそうです。

一覧では事実の概要と「注目する理由」を優先し、詳細で「期待される機会」まで読める形なら、現在の Signal → Opportunity の考え方も保てます。

## 4. スマホで検索から始められる画面〈優先度：高〉
- ステータス: 未着手

現在のスマホ表示は「地図→一覧→詳細」の順です。今回の用途では、開いた直後に検索や最新週へアクセスできる方が合っています。

おすすめの構成は次の形です。

| 入口 | 主な用途 |
|---|---|
| 最新週 | 空き時間に今週の共有内容を眺める |
| 探す | キーワードから全期間の過去事例を探す |
| 地図 | 地域の分布を俯瞰し、会議で探索する |

検索欄はすぐ操作できる位置に置き、詳細から戻ったときには検索条件とスクロール位置を維持します。会話中の利用では、この「戻っても探し直さなくてよい」動作が効きます。

追加するなら、次の機能も相性がよいです。

| 機能 | 役立つ場面 |
|---|---|
| **関連する過去事例** | 詳細の下に同じトピックの事例を表示し、「ほかの自治体でもやっていた？」を探す。まずは共通タグで関連付ける |
| **あとで読む・お気に入り** | 流し読みで気になった記事や、訪問先との会話で使いたい事例を保存する |
| **事例への直接リンク・要点コピー** | 「さっき話したのはこれです」と、タイトル・自治体・要点・出典を渡す |
| **最近見た事例・検索履歴** | 「この前見つけた記事」を少ない操作で再表示する |

JSONの運用では、**検索に使える具体的な日本語トピックを揃えること**もおすすめです。「行政DX」だけでなく「マイナンバーカード」「窓口改革」「オンライン申請」などを既存の関連トピックに入れておくと、検索と関連事例表示の両方に使えます。

最初の追加範囲は、**「全期間検索＋自治体別履歴＋最新週表示＋スマホの入口改善」**がよいと思います。挙げていただいた4つのユースケースに直接対応でき、毎週JSONを取り込む今の運用も活かせます。

## LLMとの接続について
**挙げた機能は、すべてLLMのAPIなしで実現できます。** 違いが出るのは「言葉が曖昧でも探せるか」「関連性をどこまで深く判断できるか」です。

まずは既存のJSONを使って検索・閲覧を整え、将来LLMで検索能力を広げる進め方が合っています。

| 機能 | LLMなしでの実現方法 | 将来LLMを接続すると |
|---|---|---|
| **全期間検索** | タイトル・概要・自治体名・トピックなどを文字検索。複数キーワードや一致箇所の強調にも対応 | 「カードを使って住民の手続きを楽にした事例」のような曖昧な説明でも探せる |
| **自治体別の履歴** | 自治体と日付で絞り込み、時系列に表示 | 「この自治体の直近半年の動き」を要約できる |
| **最新週の流し読み** | レポート週で抽出し、JSONの概要・注目する理由を表示 | 複数記事をまとめた「今週の主な動き」を生成できる |
| **スマホの入口改善** | 検索・最新週・地図への導線、戻ったときの位置保持 | LLMなしで十分に完成できる |
| **関連する過去事例** | 共通トピック・カテゴリなどで関連度を計算して表示 | 言葉やカテゴリが違っても、課題や施策の共通点から探せる |
| **あとで読む・お気に入り** | 事例のIDを端末内に保存 | LLMなしで十分。複数端末への同期は別の仕組みで対応 |
| **直接リンク・要点コピー** | ID付きリンクや、既存の概要・出典を組み合わせた文章を作る | 相手や会話の目的に合わせた紹介文を作れる |
| **閲覧・検索履歴** | 端末内に履歴を保存 | LLMなしで十分に完成できる |

特に、**検索と関連事例は、LLMなしでもかなり使いやすくできます。**

例えば「マイナンバー」の検索なら、次の工夫ができます。

- **表記揺れへの対応**：「マイナカード」と「マイナンバーカード」を同じ対象として扱う。
- **見つけやすい順番**：タイトルやトピックに一致した事例を上位にする。
- **検索候補**：取り込まれたJSONから、自治体名やトピックの候補を出す。
- **言葉の掛け合わせ**：「マイナンバー 子育て」で絞る。

ただし、「マイナンバー」と「マイナンバーカード」は対象が完全に同じではありません。略称と、意味が近い関連語は区別して扱う方が、検索結果に納得感が出ます。

将来のLLM接続を見据えるなら、今の段階では次の3点を押さえるのがおすすめです。

1. **事実と解釈を分けて蓄積する**  
   現在の「概要」「注目する理由」「期待される機会」の分離を維持します。後からLLMに渡す際も、ニュースの事実とこちらの見立てを区別できます。

2. **事例ID・自治体名・日付・出典を安定させる**  
   検索、保存、関連付け、将来の回答から元記事へ戻る導線に共通して使えます。JSONの追加項目は必要になった段階で増やせば十分です。

3. **検索処理を画面から切り離しておく**  
   最初は文字検索を使い、後から意味検索を追加できる構成にします。LLM導入後も、地図の地域選択やキーワード検索は引き続き役立ちます。

今回の実装順は、冒頭の方針に合わせて **①全期間検索 → ②自治体履歴 → ③最新週表示 → ④スマホの入口改善** とします。関連事例・保存・共有・履歴、およびLLMによる曖昧検索や横断要約は、その後の拡張として検討します。

この順なら、LLM接続前から日常で使えるようになり、「どんな言葉では見つからなかったか」という実際の利用経験を、LLM導入時の改善対象にできます。
