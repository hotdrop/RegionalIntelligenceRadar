# Regional Intelligence Radar v0.2.0

## 概要

Regional Intelligence Radarは、地域創生、地域活性化、自治体DX、行政施策、地域課題に関する情報を、単なるニュース一覧ではなく「地域のSignal」として俯瞰するためのWebアプリです。現段階では本番サービスではなく、個人利用を前提とした完全ローカルのPoCです。人間が手動で配置した週次レポートを読み込み、Intelligence Console風の1画面で、Signalの探索・比較・詳細確認を行います。

## 目的

このPoCの最重要目的は、Webアプリ自体の完成度を検証することではなく **「地域創生・自治体・行政に関する有益なSignalを、継続的に発見できるか」** を検証することです。将来的には、発見した情報を以下の流れへ発展させることを想定します。

```text
Signal(シグナル) → Opportunity(機会) → Hypothesis(仮説) → Experiment(検証)
```

v0.2.0の対象は、その起点となるSignalとOpportunityを、会議で見やすく、魅力的に探索・確認できることです。Webアプリはこの検証を支援するビューアであり、API、DB、認証、自動収集、クラウド連携は備えていません。

## PoCの基本フロー

運用フローは以下のとおりです。

1. ChatGPTの定期タスクで、毎週地域創生・自治体・行政に関するSignal候補を収集する
2. ChatGPTがGoogleドキュメントとしてレポートを出力する
3. 同じ内容をWebアプリ用JSON形式にも整形する
4. JSONファイルを人間が手動でこのプロジェクトへコピーする
5. Webアプリをローカルで起動する
6. 配置されたJSONファイルを読み込み、Radar上に表示する
7. 過去週のJSONも保持し、履歴として参照可能にする

JSONのコピーは意図的に手動運用としており、自動同期機能はありません。

## 表示と地域選択

全期間・全自治体・全カテゴリのSignalをまとめて表示します。週・自治体・カテゴリのフィルターや最新シグナル帯は設けません。カテゴリ・自治体は各Signalの説明として表示します。

地図で都道府県を選ぶと、その地域の全期間のSignalに絞り込み、先頭を詳細表示します。同じ都道府県の再選択、または倍率操作の隣の「地域選択を解除」で全国へ戻り、全期間の先頭を選択します。解除時も地図の倍率・位置は維持します。該当なしの場合は一覧と詳細を空表示にします。

地図の件数集計と一覧の母数は全期間です。ヘッダーのLATEST REPORTは最新週、SIGNALSは全期間の総件数で、都道府県選択には連動しません。

## モバイル表示

950px以下ではタイトルの下に統計を常時表示し、地図→一覧→詳細を縦に並べます。地図と一覧の高さはそれぞれ480pxです。表示配分の切替ボタンは設けません。

一覧は領域内スクロール、詳細は自然な高さのページスクロールです。一覧でSignalを選ぶと詳細先頭へフォーカスと表示位置を移し、prefers-reduced-motionでは即時移動します。地図見出しと操作は狭い幅で二段にし、主要ボタンは44px以上の操作領域を確保します。PCの初期配分は地図55%、右側領域の一覧70%とし、ドラッグとキーボードでサイズを変更できます。

利用環境は完全なローカル環境です。構成を単純に保つため、依存関係は必要最小限に限定しています。以下の技術と運用はv0.2.0の対象外です。

## データ構造

SignalデータはTypeScriptファイルに直接定義せず、プロジェクト内の `data` ディレクトリへ週単位のJSONファイルとして配置します。読み込み、絞り込み、表示用メタデータなどのTypeScriptコードは `lib` に分離しています。

例：

```text
regional-intelligence-radar/
├─ data/
│  ├─ 2026-08-24.json
│  ├─ 2026-08-31.json
│  ├─ 2026-09-07.json
│  └─ ...
├─ lib/
│  ├─ loadSignalArchive.ts
│  ├─ filterSignals.ts
│  └─ ...
├─ components/
├─ types/
└─ ...
```

`data` ディレクトリには週次JSONだけを配置します。ファイルは命名規則に基づいて自動検出されるため、新しいJSONの追加に伴うコードや設定の変更、`index.json` のような管理ファイルの更新は発生しません。

## JSONフォーマット

各JSONは1週間分のSignalを保持します。以下の形式を基本としています。

```json
{
  "week": "2026-08-24",
  "generatedAt": "2026-08-24T09:00:00+09:00",
  "signals": [
    {
      "id": "2026-08-24-001",
      "prefecture": "長野県",
      "municipality": "○○市",
      "category": "Regional Mobility",
      "title": "AIオンデマンド交通の実証実験を開始",
      "summary": "高齢者や交通空白地域の移動手段確保を目的とした実証実験。",
      "importance": "HIGH",
      "publishedAt": "2026-08-20",
      "whyItMatters": "人口減少地域における公共交通維持の新しいアプローチとして注目できる。",
      "opportunity": "地域通貨、健康施策、高齢者支援との連携可能性がある。",
      "relatedTopics": [
        "Regional Mobility",
        "Aging Society"
      ],
      "sourceUrl": "https://example.com"
    }
  ]
}
```

JSONフォーマットはPoCに必要な情報だけを持つ単純な構造です。フィールドの追加は明確な表示・運用上の必要性がある場合に限定します。

## データ読み込み

`lib/loadSignalArchive.ts` は `import.meta.glob` によって `data/*.json` をサーバー境界で自動検出し、すべての週次レポートを読み込みます。各ファイルは読み込み時に、ファイル名と `week` の一致、日付と日時の形式、カテゴリ、重要度、URL、アーカイブ全体でのSignal IDの一意性を検証します。検証済みのデータは最新週から降順に並べたアーカイブへ変換され、ブラウザからローカルファイルシステムへ直接アクセスすることはありません。

アーカイブから取得できる情報は以下のとおりです。

- 最新週
- 過去週
- 全Signal
- 特定週のSignal
- 特定都道府県のSignal

## 最重要方針

このプロジェクトはPoCであり、技術的に高度なシステムを構築すること自体を目的としていません。検証対象は **「毎週収集した自治体・行政情報から、本当に有益なSignalを継続的に発見できるか」** です。Webアプリはその検証を支援するビューアとして、シンプルで軽量かつ変更しやすい構成を採用しています。複雑な設計と単純な設計のどちらでも要件を満たせる場合は、単純な設計を採用します。
