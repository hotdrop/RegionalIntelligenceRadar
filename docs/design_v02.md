# Regional Intelligence Radar PoC — 設計変更指示

現在実装中の Regional Intelligence Radar を、以下のPoC方針に合わせて修正してください。

今回のPoCの目的は、Webアプリ自体の完成度を検証することではありません。

最重要目的は、

**「地域創生・自治体・行政に関する有益なSignalを、継続的に発見できるか」**

を検証することです。

Webアプリは、そのSignalを会議で見やすく・魅力的に表示するためのビューアです。

そのため、API、DB、認証、自動収集、クラウド連携などは一切追加しないでください。

## PoCの基本フロー

運用フローは以下とします。

1. ChatGPTの定期タスクで、毎週地域創生・自治体・行政に関するSignal候補を収集する
2. ChatGPTがGoogleドキュメントとしてレポートを出力する
3. 同じ内容をWebアプリ用JSON形式にも整形する
4. JSONファイルを人間が手動でこのプロジェクトへコピーする
5. Webアプリをローカルで起動する
6. 配置されたJSONファイルを読み込み、Radar上に表示する
7. 過去週のJSONも保持し、履歴として参照可能にする

JSONのコピーは意図的に手動運用とします。

自動同期機能は実装しないでください。

## データ構造の変更

現在モックデータをTypeScriptファイルなどに直接定義している場合は、その構造を廃止してください。

代わりにプロジェクト内へ、週単位のJSONファイルを配置する構成にしてください。

例：

```text
regional-intelligence-radar/
├─ data/
│  ├─ 2026-08-24.json
│  ├─ 2026-08-31.json
│  ├─ 2026-09-07.json
│  └─ ...
├─ lib/
│  ├─ loadSignalArchive.ts
│  ├─ filterSignals.ts
│  └─ ...
├─ components/
├─ types/
└─ ...
```

Webアプリ起動時に、`data` ディレクトリ配下のJSONファイルをすべて読み込んでください。
`data` には週次JSONだけを置き、読み込み・絞り込み・表示用メタデータなどのTypeScriptコードは `lib` に分離してください。

新しいJSONを追加した場合、できる限り追加実装や設定変更なしで読み込める構造にしてください。

`index.json` のような管理ファイルを毎回手で更新する必要はありません。

## JSONフォーマット

各JSONは1週間分のSignalを保持します。

以下の形式を基本としてください。

```json
{
  "week": "2026-08-24",
  "generatedAt": "2026-08-24T09:00:00+09:00",
  "signals": [
    {
      "id": "2026-08-24-001",
      "prefecture": "長野県",
      "municipality": "○○市",
      "category": "Regional Mobility",
      "title": "AIオンデマンド交通の実証実験を開始",
      "summary": "高齢者や交通空白地域の移動手段確保を目的とした実証実験。",
      "importance": "HIGH",
      "publishedAt": "2026-08-20",
      "whyItMatters": "人口減少地域における公共交通維持の新しいアプローチとして注目できる。",
      "opportunity": "地域通貨、健康施策、高齢者支援との連携可能性がある。",
      "relatedTopics": [
        "Regional Mobility",
        "Aging Society"
      ],
      "sourceUrl": "https://example.com"
    }
  ]
}
```

必要に応じて多少のフィールド追加は構いませんが、過剰に複雑化しないでください。

## TypeScript型定義

JSONフォーマットに対応する型を明示的に定義してください。

例えば以下のような責務を分けてください。

```text
Signal
WeeklySignalData
SignalCategory
Importance
```

JSON読み込み後のデータはTypeScript上で型安全に扱ってください。

ただし、大規模なDomain LayerやRepository Patternなどは不要です。

PoCとして理解しやすい構造を優先してください。

## データ読み込み

`data/*.json` を読み込み、すべてのSignalをアプリ内で扱えるようにしてください。

Next.jsのServer ComponentやNode.js側でファイルシステムを利用するなど、現在の構成に最も自然な方法を採用してください。

ブラウザ側から直接ローカルファイルシステムへアクセスする構成にはしないでください。

読み込んだデータから最低限以下を取得できるようにしてください。

- 最新週
- 過去週
- 全Signal
- 特定週のSignal
- 特定都道府県のSignal
- 特定カテゴリのSignal

## UIの変更

既存のIntelligence Console風UIは基本的に維持してください。

ただし、「リアルタイム監視システム」のような見せ方にはしないでください。

今回のデータは週次更新です。

そのためステータス表示も、

```text
LATEST REPORT
2026-08-24

SIGNALS
12
```

のような表現に変更してください。

期間・自治体の選択欄やカテゴリ行は、選択肢そのものから用途と選択状態が分かる構成とし、同じ情報を繰り返す見出しや選択条件の要約領域は表示しません。地図も名称、ズーム操作、選択中の都道府県に絞り、対応先のない画面識別子や件数の重複表示は避けます。

`REALTIME`
`LIVE`
`ONLINE FEED`

など、実態と異なる表示は使用しないでください。

## 週切り替え

過去データを比較・参照できるようにしてください。

最低限以下を実装してください。

- Latest
- 過去の各週
- All

週を選択すると、その週のSignalだけを表示します。

`All` の場合は全期間を表示します。

UIはドロップダウンでもタブでも構いません。

既存デザインとの統一感を優先してください。

## Signal履歴

過去のSignalを蓄積していくことを前提としてください。

同じカテゴリや自治体のSignalを後から追える構造にしてください。

ただし、v0.1では高度な類似検索やAI検索は実装しません。

最低限、

- 同じ都道府県
- 同じ自治体
- 同じカテゴリ

で絞り込み可能なら十分です。

## Signal詳細

Signal詳細には既存の以下の項目を維持してください。

- SIGNAL
- WHY IT MATTERS
- OPPORTUNITY
- RELATED TOPICS
- SOURCE

さらに、

- REPORT WEEK
- PUBLISHED AT

を表示してください。

これにより、そのSignalがいつ収集されたものなのか確認できるようにしてください。

## ワークスペースの表示配分

1440〜1920pxの横長画面では、情報探索から詳細確認へ移る認知フローに合わせて、マップ・Signal一覧・Signal詳細の表示配分を変更できるようにします。

- 初期表示は「探索」とし、マップ55%、右列45%、右列内はSignal一覧70%、Signal詳細30%とする
- 「探索」「均等」「詳細」のプリセットを用意し、ワンクリックで表示配分を切り替えられるようにする
- マップと右列の境界、およびSignal一覧とSignal詳細の境界はドラッグで自由に変更できるようにする
- マップ幅は35〜65%、Signal一覧の高さは30〜70%の範囲に制限し、各領域が操作不能になるほど縮小させない
- 境界はキーボードでも操作可能とし、矢印キーで2%、Shift＋矢印キーで5%、Home／Endで最小・最大へ変更できるようにする
- Signal選択による自動的な表示配分変更は行わず、ユーザーが選んだ配分を維持する
- 表示配分は永続保存せず、再読み込み時は「探索」に戻す
- 950px以下ではリサイズ操作を無効化し、マップ、Signal一覧、Signal詳細を固定高で縦に並べる

## Mapについて

既存の日本地図は維持して構いません。

ただし地図はこのPoCの主要機能ではありません。

地図実装の改善や高度化に時間をかけないでください。

既存の都道府県選択機能が動いていれば十分です。

地図表示は現在の全体表示を最小の100%とし、200%まで25%刻みで拡大・縮小できるようにします。拡大中はドラッグと矢印キーによる範囲内の移動を可能にしますが、ホイール、ピンチ、選択地域への自動ズームなどの高度な地図操作は追加しません。

## 今回の優先順位

優先順位は以下です。

1. JSONファイルを追加するだけでSignalを読み込める
2. 過去週のSignalを蓄積できる
3. 週単位で切り替えて閲覧できる
4. Signal詳細が読みやすい
5. 都道府県・カテゴリで絞り込める
6. 現在のスタイリッシュなUIを維持する
7. その他の演出

特に、アニメーションや高度なUI改善よりデータ差し替えの容易さを優先してください。

## 完了条件

以下を満たしたら今回の修正は完了です。

- `npm install`
- `npm run dev`

で正常に起動する。

## 最重要方針

このプロジェクトは現在PoCです。

技術的に高度なシステムを作ることが目的ではありません。

検証したいことは、

**「毎週収集した自治体・行政情報から、本当に有益なSignalを継続的に発見できるか」**

です。

Webアプリはその検証を支援するビューアとして、シンプル・軽量・変更しやすい状態を維持してください。

実装を複雑にする判断と、単純にする判断で迷った場合は、原則として単純な方を選択してください。
